# Research evidence

Own factual investigation and source-to-claim evidence, not framework selection or architecture approval. A software feasibility question can need this evidence; its decision is owned by the applicable decision method. Loading this Skill does not authorize new effects, external services or another Agent.

## Assignment and execution mode

Use the supplied question, existing sources and confirmed context to identify the factual gap and required output. Reuse adequate current evidence rather than research merely to fill a stage.

- **Current context / already delegated worker:** investigate here with the available tools. Being asked to use `research` does not require spawning another worker for the same assignment.
- **Delegated/background research:** preserve this original capability when requested or when a genuinely separable investigation benefits from concurrency or isolation, within actual delegation authority and remaining resources. The coordinator gives the worker the question, existing evidence, source scope, output location and time/attempt limits; the worker executes the investigation here. Further subdivision needs a distinct evidentiary purpose and covered resources, not another automatic layer from this Skill.
- If independent execution cannot continue while a worker reads, disclose that limit rather than claiming background concurrency. A blocked delegation can be completed here only if it still meets the requested isolation/method and existing authority; otherwise report the gap.

## Evidence method and output

Investigate against primary sources: official documentation, source code, specifications and first-party APIs. Follow each material claim to the source that owns it. Preserve the relevant version/date/context; distinguish documented support, inspected source, actual execution, inference, conflict and unknowns. Do not turn missing evidence into a positive capability claim.

Return the answer to the factual question with claim-level citations and limitations. For the original saved-note workflow, write one cited Markdown file in the caller's assigned destination or the repo's existing notes convention; if none exists, use a sensible existing location and report it. Preserve that deliverable when requested. With read-only effects or an answer-only request, return the cited evidence in the response and state any deferred note rather than writing. Reuse the authoritative existing record instead of making duplicate stores.

Finish when the assigned claims are supported or the material evidence gaps/limits are explicit. Evidence gathering itself neither selects a framework nor starts implementation, approval interviews or a broader system audit.
