# Test Skill

Own Skill/Harness evaluation and its bad-case evidence, independently of a Runner or software lifecycle procedure. Global owns authority and phase gates. Select the applicable branch below; a capture or packaging request is not a full evaluation.

## Lightweight evidence and packaging branches

- Evidenced Agent-process correction, delivery failure/rework, or explicit process-bad-case capture: read the applicable [feedback/regression](../../references/feedback-regression.md) capture or improvement-proposal section. This branch covers process failures during planning, research and documentation as well as coding. A new requirement, ordinary clarification or newly reported application defect alone does not trigger capture. Continue the primary authorized task; capture authorizes neither a model trial nor an improvement/adoption. Respect read-only/candidate-only effects and report deferred registration where necessary.
- Static Skill-package validation: read [Packaging](references/evaluation.md#packaging), then stop with the requested packaging result. Do not enter behavioral evaluation merely to validate a package.

Only when assessment/design/execution/comparison/disposition is actually needed, select its mode below.

## Mode and required guidance

| Mode | Deliverable and loading condition |
|---|---|
| Diagnose | Supported attribution or exact evidence gaps from existing material. Read [Diagnosis](references/evaluation.md#diagnosis); no new run or modification is implied. |
| Design | Inputs, independent criteria, observable evidence, selected level and proposed budget. Read [Test selection](references/evaluation.md#test-selection) and [Case definitions](references/evaluation.md#case-definitions); for an A/B plan also read [Before execution](references/evaluation.md#before-execution) to define its conditions. Stop before execution unless separately covered. |
| Execute | Actual authorized evidence and classified incomplete items. Read [Before execution](references/evaluation.md#before-execution) and [Execution and assessment](references/evaluation.md#execution-and-assessment). |
| Compare | Comparability and supported differences for identified evidence. Read relevant conditions in [Before execution](references/evaluation.md#before-execution) and [After execution](references/evaluation.md#after-execution). Comparison alone does not authorize another run or revision. |
| Decide | Recommend Adopt, Revise, Reject or Inconclusive under [Disposition](references/evaluation.md#disposition); a recommendation does not apply the change. |

Modes can be internal steps of one authorized outcome. Resume valid definitions, evidence and approvals; do not replay the entire evaluation sequence or seek approval only because a Skill/mode boundary changed. Explicit diagnosis-only/design-only limits remain stops. For a complex or resumed multi-stage evaluation, use the shared [continuation record convention](../../references/integration.md#fixed-input-and-project-records) in the existing plan/report; a single bounded Trace assessment needs no extra planning record.

## Shared evidence contract

Use independent requirements/raw sources, not the executor's desired answer or self-assessment. Distinguish input/oracle, routing, method behavior and Harness/environment failures. A Skill read alone proves neither correct nor incorrect execution. Unknown, blocked and unexecuted items cannot become PASS. A repair claim needs comparable Baseline evidence; one Candidate smoke does not establish superiority or adoption. Missing attribution may correctly end with NO_CHANGE.

## Conditional branches

- Missing/changing Agent Evaluation cases: use this Skill's [Case definitions](references/evaluation.md#case-definitions). That section owns Agent assertions and evidence standards; software test design is supporting guidance only when its stated condition applies.
- An evaluation actually needing existing cases, comparison-budget guidance or adoption records: read only the applicable [feedback/regression](../../references/feedback-regression.md) section; an already supplied Trace does not require a library scan.
- Preparing or validating a Harness/Skill/rule candidate: read [Protocol candidate work](references/evaluation.md#protocol-candidate-work).
- Actually authoring a Skill: read [Skill authoring](references/evaluation.md#skill-authoring); evaluating a Skill does not itself activate authoring.

Section links identify required guidance; their fragments do not automatically constrain file-tool output. Retrieve needed sections with existing file tools rather than loading the whole Reference or every target by default. Known independent requirements can be obtained together; preserve genuine evidence dependencies and pending approvals.

## Completion

Deliver the authorized outcome/mode result with item-level evidence, unknown scope and next permitted action. Stop affected execution on invalid conditions, missing necessary evidence or exhausted limits; preserve attempts and continue independent authorized work. Use verified existing scripts for deterministic operations where needed; diagnosis/design require no Runner. Infrastructure work and new model calls need actual authority, not a mode label.
