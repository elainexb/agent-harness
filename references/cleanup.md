# Clean the actual change after green

For this cleanup pass, use installed `deslop` at its native catalogue path if not already loaded; entry from that Skill reuses it rather than reloads it. Use the [fixed-input scope](integration.md#fixed-input-and-project-records), including relevant WIP/new files and the actual base; do not assume main exists. Read the archived [no-comments method](upstream/pstack/no-comments/source.md) and [comment review criteria](upstream/pstack/no-comments/comment-sicko.md) for affected comments. This is an adapted cleanup pass: no Cursor-specific agent/model selection, no automatic architect invocation, no ambiguity-driven deletion.

After the initial behavior checks pass, simplify the changed code before freezing it for independent review. Inspect deep nesting, repeated branches/scans, needless loops, dead code, unnecessary indirection, casts bypassing types and unjustified checks/catches on genuinely trusted paths. Prefer clear guard clauses or a small helper when they remove complexity. A `for` loop is not itself a defect: keep it when it expresses iteration, ordering, short-circuiting or async control clearly. Do not replace a clear loop with a dense chain just to remove the word `for`.

Remove comments that merely narrate obvious code, stale banners and dead commented-out code. Preserve legal/license notices, public API contracts, valid tool directives and genuinely non-obvious external platform/dependency/protocol constraints. Trace nearby code and actual callers before judging a constraint. If the reason is uncertain, retain it and report the uncertainty rather than silently removing a safeguard. Inspect safety/type suppressions and propose the actual root-cause fix; do not delete a suppression while leaving broken code. Do not remove useful context just to reach a deletion count.

The developer applies minimal substantiated edits. The independent Standards leaf subsequently checks the same changed code and comments with a fresh perspective; it reports suggestions only and does not edit or launch another comment reviewer. This folds Comment Sicko's perspective into the existing two-leaf budget instead of assuming Cursor's agent exists.

Preserve observable behavior. For a pure cleanup/refactor task, establish meaningful existing or characterization checks green BEFORE editing and run the same checks green afterward. Do not break code to manufacture a red or claim a past implementation was test-first. For behavior-changing fixes found during cleanup, follow mandatory Matt TDD and existing scope/architecture approval. Rerun affected checks after cleanup, preserve failures and changes, and freeze that resulting candidate for review. A substantive architecture change still requires approval before implementation.
